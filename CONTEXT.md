# Domain glossary

**Icon** — the pair of representations a `CheckboxConfig` carries for rendering: a *filled* shape (`icon`, a single SVG path's `d` attribute, plus `viewBox`) sourced from fontawesome.com, and a *stroke* shape (`customIconData`, a set of raw SVG element strings plus `viewBox`) sourced from lucide.dev — or picked by name from Obsidian's own icon registry via `getIcon()` (`src/icon-suggest.ts`, bridged into `customIconData` by `iconDataFromElement()` in `src/icon.ts`), which is the same source data since Obsidian's built-in icons are Lucide. Which representation renders is decided by the plugin-wide `settings.iconStyle` ('filled' | 'stroke'), not by the checkbox itself — a checkbox can carry both, one, or (transiently, mid-edit) neither. When the representation matching the active style is missing, rendering falls back to the other representation before giving up. Everything style-specific (parsing pasted SVG, rendering, mask data URLs, editable source, the UI strings for each source site) sits behind `iconsFor(style)` in `src/icon.ts`, so callers hold one `Icons` object and never branch on the style. Stroke data is always stored as `elements` (SVG element strings); the older `paths` form is converted on load and import by Settings normalisation.

**Settings normalisation** — the one step that brings any settings object (from `loadData()`, an imported backup, or nothing at all) to the current shape: missing top-level fields come from `DEFAULT_SETTINGS`, each checkbox gets a `viewBox`, and a checkbox without `customIconData` inherits the default with the same symbol. Defined by `normalizeSettings()` in `src/settings.ts`; load and import both pass through it, so they cannot diverge.

**Symbol** — the single character between the brackets in `- [x]` that identifies a checkbox type (`CheckboxConfig.symbol`). Unique within the checkbox list: `css-generator.ts` keys its rules by symbol, so a second checkbox with the same symbol silently stops the first from rendering. Enforced by `src/checkbox-list.ts` (add, edit) and `deserializeConfig()` (import).
